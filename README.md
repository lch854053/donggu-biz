# 동구 사업자·상권 조회

광주 동구 행정·실무자를 위한 사업자 상태 일괄조회와 상가 업종 분석 서비스입니다.

## 기능

### 사업자 조회

- **사업자 상태조회**: 사업자등록번호 계속·휴업·폐업 상태 일괄조회, 상태별 필터와 CSV 다운로드
- **사업자등록정보 진위확인**: 사업자등록번호·개업일자·대표자명을 국세청 등록정보와 대조하고 일치 시 과세 유형·사업자 상태를 표시
- **4대보험 사업장 조회**: 국민연금과 고용·산재보험 스냅샷을 한 목록에서 사업장명·주소·행정동·업종·자료 구분·사업 구분으로 조건검색하고, 국민연금 가입자 수와 고용·산재 상시근로자 수·성립일자·사업장 식별정보를 함께 확인합니다. 같은 사업자등록번호의 보험 기록은 한 행으로 묶고 사업장관리번호별 수치는 상세에서 구분합니다. 법인번호가 정확히 매칭되고 공개 재무제표가 있는 기업은 최근 3개년 요약재무정보도 상세에 표시합니다.

### 소상공인 조회

- 광주 동구 상가업소 지도와 상호 배타적인 행정동·주요상권 조회
- 매월 갱신하는 상가정보와 행정안전부 인허가(영업 중) 보완 스냅샷의 업소를 지도와 표에서 조회
- 일반음식점·휴게음식점·제과점·미용업·이용업·담배소매업·숙박업·노래연습장업을 관리번호·주소·좌표로 중복 제거
- 스냅샷 메타데이터에 원천별 건수·매칭 건수·추가 건수·좌표 누락 건수를 기록
- 선택한 행정동 또는 주요상권의 상위 10개 업종 소분류 분석
- 지도에서 주요상권을 선택하면 기존 점포·클러스터 마커로 업소 위치를 확인
- `상권 상세 분석` 하위 탭에서 외곽 경계선·배경 지도 없이 선택 상권의 건물 윤곽과 업종 분류만 기본 표시
- 업종 데이터가 있는 건물에 마우스를 올리면 연결 업소명·업종·주소를 표시하며, 한 건물에 여러 업소가 있으면 업소 수가 가장 많은 업종으로 색상 분류
- 지도와 동일한 상가정보를 행정동·업종 대분류·주요상권 조건으로 표 조회하고, 업소명 또는 업종 대분류로 정렬해 XLSX로 다운로드
- 건물 윤곽은 `data/figure-ground/manifest.json`과 cell GeoJSON에 보관한 2026년 8월 정적 스냅샷이며, 선택 상권과 겹치는 cell만 불러옵니다.
- 업종 연결은 현재 동구 코드와 기존 동구 코드 PNU를 함께 비교하고, PNU가 어긋난 점포는 같은 필지·거리 조건으로 보정합니다. 연결된 점포의 업종이 비어 있으면 `업종 미확인`, 점포를 찾지 못한 건물은 `점포 미연결`로 표시합니다.

## 고용·산재보험 자료 갱신

고용·산재보험 자료는 API를 실시간 호출하지 않고 CP949 원본 `data/employment_insurance_donggu.csv`와 정규화한 `data/employment_insurance_donggu.json`을 함께 보관합니다. 현재 스냅샷은 **2025년 12월 31일 기준**이며, 광주 동구 사업장 6,924건을 담고 있습니다.

새 파일을 받으면 원본 CSV를 교체하고, 파일의 기준일을 인자로 넣어 변환합니다.

```bash
npm run update-employment-insurance -- --source-updated-at 2025-12-31
npm run enrich-insurance-admin-dongs
npm test
```

변환 스크립트는 17개 필수 컬럼, 행별 열 개수, 연번 중복, 보험구분 값과 날짜·상시근로자 수 형식을 검사합니다. 성립일자는 원본 Excel 날짜 serial에서 ISO 날짜로 변환합니다. 이어서 `JUSO_API_KEY`를 사용하는 행정동 보강을 실행하며, 모호한 주소는 추정하지 않고 미확인으로 남깁니다. `data/employment_insurance_donggu.csv`, `data/employment_insurance_donggu.json`, `data/insurance_admin_dongs.json`을 함께 커밋해야 화면의 자료가 바뀝니다.

GitHub Actions `Remind Dong-gu employment insurance data refresh`가 매년 **12월 31일 09:00(KST)**에 연말 갱신 확인 Issue를 만듭니다. 필요하면 Actions의 `Run workflow`로 즉시 실행할 수 있습니다.

## 4대보험 사업장 조건검색

조회 조건은 다음과 같습니다.

- **사업장명·주소·업종 검색** — 두 자료의 이름·주소·업종·사업장 식별번호를 함께 검색합니다.
- **사업자등록번호 검색** — 6자리 이상 입력합니다.
- **행정동** — 도로명주소 검색 API로 확정된 행정동을 기준으로 조회합니다. 주소가 모호한 사업장은 전체 조회에는 포함되지만 특정 행정동 조회에서는 제외됩니다.
- **업종 대분류** — `lib/nps.js`의 국민연금 분류표를 기준으로 목록을 만들고, 국민연금 업종이 미상인 연결 사업장만 고용·산재 제11차 업종코드를 같은 대분류 의미로 매핑해 보강합니다. 끝에 **업종 미상**을 한 항목으로 덧붙입니다.
- **국민연금 가입 상태** — 기본은 국민연금 가입 상태가 **등록**인 사업장만 보여 주고, **국민연금 탈퇴 사업장 포함**을 선택하면 탈퇴 사업장도 함께 나옵니다.

조건을 바꾼 뒤 **조회 시작**을 눌러야 결과에 적용됩니다. 조회 결과는 국민연금 등록일과 가입자 수 기준으로 정렬할 수 있으며 **XLSX**로 내려받을 수 있습니다.

국민연금만 표시되거나 고용·산재만 표시되거나 가입 데이터가 조회되지 않는 것은 미가입을 뜻하지 않습니다. 해당 기관 자료에 포함되지 않은 경우일 수 있습니다.

### 조회는 두 스냅샷을 안전하게 연결합니다

국민연금 목록 API는 자료생성년월마다 사업장을 한 건씩 쌓아 돌려주어 동구 전체가 **월별 이력 13,295건**이고, 업종·등록일·가입자 수는 목록에 없어 사업장마다 상세조회를 한 번씩 더 불러야 합니다. 화면에서 이 값을 표시·정렬하려면 실시간으로 감당할 양이 아니므로 미리 상세를 받아 둡니다.

그래서 조회 화면은 **미리 받아둔 동구 국민연금 스냅샷(`data/nps_donggu.json`)과 고용·산재보험 스냅샷(`data/employment_insurance_donggu.json`)**을 함께 읽습니다. 국민연금 월별 이력을 접은 **사업장 2,322개**와 고용·산재보험 원본 **6,924개 행**을 사업자등록번호 앞 6자리와 정규화한 사업장명으로 연결합니다. 법인 표기, 괄호 안 대표·직장 표기, 건설 일용·일괄 꼬리표 차이도 보정하되, 완화된 이름이 여러 후보를 가리키면 도로명까지 일치할 때만 연결합니다. 고용·산재 원본은 **사업자등록번호가 같은 모든 행을 한 회사 그룹으로 묶고**, 사업장관리번호별 근로자 수·성립일자·사업 구분은 상세에서 관리번호별 묶음으로 표시합니다. 연결할 수 없는 자료도 별도 행으로 남깁니다. 국민연금 API는 **상세 카드와 월별 추이**에만 씁니다.

대신 자료는 실시간이 아닙니다. 상단 안내에는 통합 자료가 연 1회 갱신된다고 표시하며, 국민연금과 고용·산재보험의 원본 기준일이 다를 수 있으므로 자료 사이의 시점 차이를 고려해야 합니다.

## 같은 사업장이 여러 건으로 보이는 이유

국민연금 API는 자료생성년월(`dataCrtYm`)마다 사업장을 한 건씩 쌓아 돌려줍니다. 그래서 `광주은행`으로 검색하면 같은 사업장이 기준월 수만큼 나옵니다. 국민연금 스냅샷은 **사업장명 + 사업자등록번호 앞 6자리 + 도로명주소**가 같으면 한 사업장으로 보고 가장 최근 기준월 한 건만 남깁니다. 고용·산재보험은 사업자등록번호가 같으면 한 행으로 묶되, 사업장관리번호별 원본 기록은 상세의 각 관리번호 소제목 아래와 XLSX에 남깁니다.

국민연금 사업장은 주소가 다르면 다른 사업장(지점)으로 보고 합치지 않습니다. 반면 고용·산재 원본은 같은 사업자등록번호라는 기준을 우선하므로 관리번호별 주소가 다르더라도 한 회사 행에 묶고 각 관리번호 묶음 안에 주소를 보존합니다. 연결되지 않는 자료도 누락하지 않고 별도 행으로 남기므로, 통합 화면의 건수는 두 자료의 연결 결과와 고용·산재 회사 그룹을 반영합니다.

상세 카드는 표 맨 아래가 아니라 누른 행 바로 아래에 한 줄을 끼워 펼치고, 같은 행을 다시 누르면 접습니다. 카드에서는 스냅샷에 함께 담아 둔 달마다의 `seq`로 월별 추이를 불러 그래프 세 개로 보여줍니다 — 가입자 수, 당월 고지금액, 그리고 신규 취득·상실 가입자(같은 달을 나란한 막대로). 지표마다 단위가 달라 축을 겹치지 않고 그래프를 따로 그리며, 최대 24개월까지 표시합니다. 시점마다 수치를 적되 라벨이 겹칠 만큼 촘촘하면 2~3개월 간격으로 솎아냅니다.

## 보험 데이터의 한계

국민연금 가입 사업장 내역 API는 **사업자등록번호를 앞 6자리까지만** 제공하고 **주소도 건물번호 없이 도로명까지만** 일반화해 제공합니다. 따라서 개별 사업자를 특정할 수 없고 국세청 사업자 상태조회 결과와 자동으로 연결되지 않으며, 도로명별 구분은 건물 단위가 아닙니다. 목록 API에는 가입자 수가 없어 가입자 수는 개별 사업장 상세조회에서만 확인할 수 있습니다. 국민연금 미가입 사업장은 빠지므로 지역 전체 사업체 수와 다릅니다.

고용·산재보험 자료는 근로복지공단 연말 원본을 변환한 정적 자료입니다. 국민연금과 고용·산재보험은 기준일과 사업장 식별체계가 다르므로, 이름 별칭·사업자등록번호 앞 6자리·도로명으로도 안전하게 연결되지 않는 사업장은 별도 행으로 표시합니다. 이 서비스에는 건강보험 자료가 포함되지 않습니다.

## 기업 재무정보

고용·산재 자료에서 10자리 사업자등록번호와 법인 표기가 있는 사업장을 금융위원회 기업기본정보의 기업명 후보와 대조합니다. API 응답의 사업자등록번호가 완전히 같고 유효한 법인등록번호가 하나일 때 우선 매칭합니다. 후보 사업자번호가 비어 있는 경우에는 법인명이 정확히 같고 도로명·건물번호 주소가 일치하는 단일 법인만 주소 보강 매칭합니다. 다른 사업자번호가 있거나 복수 법인이 잡히면 자동 연결하지 않습니다.

확정 법인은 상세카드의 사업자등록번호 옆에 법인등록번호를 표시하고, 금융위원회 기업 재무정보에서 최근 3개년 요약재무제표를 수집합니다. 상세 화면은 별도재무제표를 우선하고 없으면 연결재무제표를 표시합니다. 이 수치는 동구 지점의 실적이 아니라 법인 전체 실적이며, 자료가 없다고 폐업·부실 또는 매출이 없다는 뜻은 아닙니다.

```bash
npm run update-corporate-matches
npm run update-corporate-financials
npm test
```

두 수집 명령에는 `FSC_SERVICE_KEY`가 필요합니다. GitHub Actions `Update Dong-gu corporate financial snapshots`가 매월 7일 04시(KST)에 스냅샷을 갱신합니다.

## 업종 대분류를 읽는 기준

업종코드(`wkplIntpCd`)는 사업장 상세조회에만 있고 목록 조회에는 없어, 화면은 스냅샷과 상세조회로 채웁니다. 이 코드는 **여섯 자리**이고 앞 두 자리가 중분류인데, 번호 체계가 최신 한국표준산업분류(10·11차)가 아니라 **2007년 개정 전의 옛 분류**입니다. 실제 응답에서 `452125`가 "일반 전기 공사업", `513421`이 "서적, 잡지 및 기타 인쇄물 도매업"이므로 45는 건설업, 51은 도매업입니다. 최신 분류표로 읽으면 건설업이 도매 및 소매업으로, 도매업이 운수업으로 밀리므로 `lib/nps.js`의 대분류 표는 옛 분류 기준으로 둡니다.

업종을 담고 있지 않은 자리표시 코드도 있습니다. 사업자등록번호가 잡히지 않는 사업장은 `999999`("BIZ_NO미존재사업장"), 업종이 지정되지 않은 사업장은 `000000`("해당없음")으로 내려옵니다. 앞 두 자리만 보면 `999999`가 중분류 99, 곧 국제 및 외국기관으로 읽히므로(광주은행어린이집이 그런 경우입니다) 두 코드는 분류하지 않고 **업종 미상**으로 둡니다.

대분류는 스냅샷에 적힌 값을 그대로 쓰지 않고 화면에서 업종코드로 다시 판정합니다. 분류 표를 고쳐도 지난달 스냅샷은 옛 판정을 담고 있기 때문입니다.

## 국민연금 API 호출 규격

`api/nps.js`는 다음 규격에 맞춰 요청합니다. 어긋나면 게이트웨이가 `국민연금 API 오류 97: CLIENT_ERROR`로 응답합니다.

- 목록 조회 `numOfRows`는 한 페이지 **최대 100건**입니다. 전량 수집은 100건씩 여러 장을 이어 받습니다.
- 상세조회 `getDetailInfoSearchV2`는 `seq`만 받습니다. 기준월(`dataCrtYm`)은 넘기지 않습니다.
- 조회 조건 파라미터 표기(카멜 `wkplNm` / 스네이크 `wkpl_nm`)와 법정동코드 형식(하위 코드만 `110` / 상위 코드 포함 `29110`)은 문서마다 설명이 엇갈립니다. 프록시는 네 조합을 순서대로 시도해 결과가 나오는 조합을 골라 기억하고, 첫 페이지가 0건이거나 파라미터 오류가 나면 다음 조합으로 넘어갑니다.
- 결과가 0건이면 응답의 `meta`에 시도한 조합과 요청 URL(서비스키는 가림)이 담깁니다. 브라우저 콘솔의 `[nps] 조회 결과 없음` 로그에서 확인할 수 있습니다.

### 오퍼레이션별로 주는 항목이 다릅니다

- 목록 `getBassInfoSearchV2`: 사업장명, 사업자등록번호 앞 6자리, 도로명주소, 가입상태, 사업장형태, 법정동코드, 자료생성년월. **업종코드가 없습니다.**
- 상세 `getDetailInfoSearchV2`: 위 항목에 더해 업종코드·업종명, 사업장 등록일·탈퇴일, 가입자 수, 당월 고지금액.
- 기간별 현황 `getPdAcctoSttusInfoSearchV2`: 월별 취득자 수, 상실자 수.

목록만으로는 업종·등록일·가입자 수를 알 수 없습니다. 그래서 조회 화면은 목록 API를 부르지 않고 **상세조회까지 마쳐 둔 스냅샷을 읽습니다**. 스냅샷을 만들 때 사업장마다 상세조회를 한 번씩 더 부릅니다. 스냅샷을 만들 때도 사업장마다 상세조회를 한 번 더 불러 업종을 채웁니다.
- `NPS_SERVICE_KEY`에는 **디코딩 키**를 넣습니다. 인코딩 키를 넣으면 키가 이중 인코딩되는데, 서버가 퍼센트 표기를 감지해 한 번 풀어 보정합니다.

국민연금 사업장 스냅샷은 `data/nps_donggu.json`에 저장되며 조회 화면의 업종·등록일·가입자 수를 채우는 데 쓰입니다. GitHub Actions `Update Dong-gu NPS snapshot` 워크플로가 매월 6일 04시(KST)에 돌리고, 저장소 Actions 탭에서 손으로도 실행할 수 있습니다. 목록 전량을 받은 뒤 사업장마다 상세조회를 한 번씩 더 부르고 주소 행정동도 보강하므로 `NPS_SERVICE_KEY`와 `JUSO_API_KEY` 저장소 Secret이 필요합니다. 공공데이터포털은 몇 분씩 연결되지 않을 때가 있어, 한 요청을 최대 6번까지 대기를 두 배씩(최대 30초) 늘려 가며 다시 부르고, 첫 조합이 오류로 끝나도 다음 조합을 이어서 시도합니다. data.go.kr 트래픽 한도(개발계정 기본 1일 1만 회)를 넘기면 운영계정 전환이나 한도 상향을 신청해야 합니다.

스냅샷은 브라우저가 조회할 때 통째로 내려받으므로 화면이 실제로 읽는 값만 담습니다 — 같은 사업장인지 가리는 이름·사업자등록번호 앞 6자리·주소와, 목록 조회에 없어 채워야 하는 업종코드·업종명·등록일·탈퇴일·가입자 수입니다. 월별 이력의 `seq` 목록은 화면이 그때그때 받은 조회 결과에서 다시 만들므로 담지 않습니다.

상가 데이터는 `data/stores_donggu.json`, VWorld 주요상권 경계는 `data/mainbiz_zones_donggu.geojson`, 수동 등록·보정 경계는 `data/manual_mainbiz_zones_donggu.geojson`에 저장됩니다. GitHub Actions는 매월 5일 API 기반 데이터를 다시 수집하며 수동 경계는 별도 파일에 보존됩니다. `SDSC_SERVICE_KEY`, 각 인허가 API 활용신청이 끝난 `LOCALDATA_SERVICE_KEY`, `VWORLD_KEY` 저장소 Secret이 필요합니다. 두 서비스키가 같은 공공데이터포털 키라면 `LOCALDATA_SERVICE_KEY`를 별도로 등록하지 않아도 워크플로가 `SDSC_SERVICE_KEY`를 대신 사용합니다.

행정안전부 인허가 API는 `OPN_ATMY_GRP_CD=5805000`(전남광주통합특별시 동구)와 영업상태코드 `01`(영업/정상)로 조회합니다. 좌표는 EPSG:5174에서 WGS84로 변환하고, 기존 SDSC 업소와 이름·주소·좌표를 순서대로 비교해 중복을 제거합니다. 인허가 자료와 SDSC 자료의 업소 식별자가 서로 다르므로, 보완 원천의 추가 건수는 실제 신규 점포 수가 아니라 현재 매칭 규칙에 따른 감사 가능한 후보 수입니다.

현재 수동 등록 경계는 산수시장, 예술의 거리, 전자의 거리, 인쇄의 거리와 무등산 보리밥거리이며, 대인시장과 남광주시장은 VWorld 원본을 수동 보정 경계로 대체합니다.

VWorld 주요상권 중 금남로4가역 1~4와 문화전당역 경계는 수집 결과와 화면에서 제외합니다.
