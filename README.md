# 동구 사업자·상권 조회

광주 동구 행정·실무자를 위한 사업자 상태 일괄조회와 상가 업종 분석 서비스입니다.

## 기능

### 사업자 조회

- **사업자 상태조회**: 사업자등록번호 계속·휴업·폐업 상태 일괄조회, 상태별 필터와 CSV 다운로드
- **국민연금 사업장 조회**: 광주 동구의 국민연금 가입 사업장을 사업장명·업종 대분류·사업장 형태·등록일·가입자 수로 조건검색, 사업장별 가입자 수·신규 취득·상실·당월 고지금액 상세조회

### 상권분석

- 광주 동구 상가업소 지도와 상호 배타적인 행정동·주요상권 조회
- 선택한 행정동 또는 주요상권의 상위 10개 업종 소분류 분석

## 국민연금 사업장 조건검색

조회 조건은 다섯 가지입니다.

- **사업장명** — 공란이면 동구 전체를 조회합니다. **이 조건만 국민연금 API에 그대로 넘어가고**, 나머지는 받아 둔 결과를 화면에서 좁힙니다. 그래서 이름을 바꾸면 다시 조회해야 하고, 나머지 조건은 바꾸는 즉시 반영됩니다.
- **업종 대분류** — `lib/nps.js`의 분류표로 목록을 만들고, 끝에 **업종 미상**을 한 항목으로 덧붙입니다. 업종을 담고 있지 않은 자리표시 코드(`000000`·`999999`)를 가진 사업장이 갈 곳입니다.
- **사업장 형태** — 전체(기본)·개인·법인. 그 아래 **탈퇴 사업장 포함 조회** 체크박스를 두어, 기본은 가입 상태가 **등록**인 사업장만 보여 주고 체크해야 탈퇴 사업장이 함께 나옵니다.
- **사업장 등록일** — 연도 범위 슬라이더입니다. 국민연금 사업장 당연적용이 1988년 10인 이상 사업장에서 시작해 1992년 5인 이상, 1999년 전 사업장으로 넓어졌으므로 그보다 이른 등록일은 나오지 않습니다. 기본 범위는 **1988년부터 올해까지**로 두고, 조회 결과가 더 이른 해를 담고 있으면 그만큼 아래로 넓힙니다.
- **가입자 수** — 범위 슬라이더입니다. 상한은 **2,000명**에서 시작해 조회 결과의 최댓값이 그보다 크면 거기에 맞춥니다. 동구에는 (주)광주은행처럼 1,500명이 넘는 사업장이 있어, 상세를 다 채우기 전에도 그런 사업장이 슬라이더 밖으로 밀려나지 않게 하려는 것입니다.

두 슬라이더는 손잡이가 양 끝에 있으면 "전체"로 보고 조건을 걸지 않습니다. 업종·등록일·가입자 수는 목록 API에 없어 상세조회로 채우는 값이라, 아직 채우지 못한 사업장이 슬라이더를 건드리지도 않았는데 사라지지 않게 하려는 것입니다. 같은 이유로 이 세 조건을 걸면 상세를 아직 받지 못한 사업장은 결과에서 빠집니다.

조건검색이 업종·등록일·가입자 수를 쓰므로 화면은 보고 있는 페이지가 아니라 **조회한 사업장 전부**의 상세를 채웁니다. 스냅샷에서 찾을 수 있는 만큼 먼저 채우고 남은 사업장만 상세조회로 부르되, 한 번의 조회에서 900건까지만 부릅니다.

### 두 가지 상한과 그 안내

동구 전체 조회(사업장명 공란)는 두 상한에 함께 걸립니다. 결과 요약 아래 노란 문장 두 개가 그것을 알립니다.

1. **수집 상한 3,000건** — 이 API는 자료생성년월마다 사업장을 한 건씩 쌓아 주므로 동구 전체의 월별 이력은 3,000건(100건 × 30페이지)을 훌쩍 넘습니다. 앞부분만 받고 멈추므로 결과는 동구 전체가 아닙니다.
2. **상세 상한 900건** — 스냅샷(`data/nps_donggu.json`)에서 찾지 못한 사업장만 상세조회 대상이 되고, 그 대상이 900개에서 끊깁니다. 채우지 못한 사업장은 업종·등록일·가입자 수 조건으로 거를 때 결과에서 빠집니다. **스냅샷을 갱신해 두면 대부분 스냅샷에서 채워져 이 상한에 닿지 않습니다.**

**업종 대분류 같은 조건을 좁혀도 이 상한은 풀리지 않습니다.** 국민연금 API로 넘어가는 조건은 사업장명뿐이고 나머지는 이미 받아 온 결과 안에서만 좁히기 때문입니다. 수집 상한을 넘어선 사업장을 보려면 사업장명을 넣어 조회 범위 자체를 좁히거나, 스냅샷을 갱신해 두어야 합니다.

## 같은 사업장이 여러 건으로 보이는 이유

이 API는 자료생성년월(`dataCrtYm`)마다 사업장을 한 건씩 쌓아 돌려줍니다. 그래서 `광주은행`으로 검색하면 같은 사업장이 기준월 수만큼 나옵니다. 화면은 **사업장명 + 사업자등록번호 앞 6자리 + 도로명주소**가 같으면 한 사업장으로 보고 가장 최근 기준월 한 건만 남깁니다.

주소가 다르면 다른 사업장(지점)으로 보고 합치지 않습니다. 조회는 조건에 맞는 월별 이력을 최대 3,000건(100건 × 30페이지)까지 모두 받은 뒤 합치므로, 화면의 건수와 페이지는 **중복을 걷어낸 사업장 수** 기준입니다. 상한에 걸리면 결과 요약에 그 사실을 표시합니다.

상세 카드는 표 맨 아래가 아니라 누른 행 바로 아래에 한 줄을 끼워 펼치고, 같은 행을 다시 누르면 접습니다. 카드에서는 접어 둔 달들의 `seq`로 월별 추이를 불러 그래프 세 개로 보여줍니다 — 가입자 수, 당월 고지금액, 그리고 신규 취득·상실 가입자(같은 달을 나란한 막대로). 지표마다 단위가 달라 축을 겹치지 않고 그래프를 따로 그리며, 최대 24개월까지 표시합니다. 시점마다 수치를 적되 라벨이 겹칠 만큼 촘촘하면 2~3개월 간격으로 솎아냅니다.

## 국민연금 데이터의 한계

국민연금 가입 사업장 내역 API는 **사업자등록번호를 앞 6자리까지만** 제공하고 **주소도 건물번호 없이 도로명까지만** 일반화해 제공합니다. 따라서 개별 사업자를 특정할 수 없고 국세청 사업자 상태조회 결과와 자동으로 연결되지 않으며, 도로명별 구분은 건물 단위가 아닙니다. 목록 API에는 가입자 수가 없어 가입자 수는 개별 사업장 상세조회에서만 확인할 수 있습니다. 국민연금 미가입 사업장은 빠지므로 지역 전체 사업체 수와 다릅니다.

## 업종 대분류를 읽는 기준

업종코드(`wkplIntpCd`)는 사업장 상세조회에만 있고 목록 조회에는 없어, 화면은 스냅샷과 상세조회로 채웁니다. 이 코드는 **여섯 자리**이고 앞 두 자리가 중분류인데, 번호 체계가 최신 한국표준산업분류(10·11차)가 아니라 **2007년 개정 전의 옛 분류**입니다. 실제 응답에서 `452125`가 "일반 전기 공사업", `513421`이 "서적, 잡지 및 기타 인쇄물 도매업"이므로 45는 건설업, 51은 도매업입니다. 최신 분류표로 읽으면 건설업이 도매 및 소매업으로, 도매업이 운수업으로 밀리므로 `lib/nps.js`의 대분류 표는 옛 분류 기준으로 둡니다.

업종을 담고 있지 않은 자리표시 코드도 있습니다. 사업자등록번호가 잡히지 않는 사업장은 `999999`("BIZ_NO미존재사업장"), 업종이 지정되지 않은 사업장은 `000000`("해당없음")으로 내려옵니다. 앞 두 자리만 보면 `999999`가 중분류 99, 곧 국제 및 외국기관으로 읽히므로(광주은행어린이집이 그런 경우입니다) 두 코드는 분류하지 않고 **업종 미상**으로 둡니다.

대분류는 스냅샷에 적힌 값을 그대로 쓰지 않고 화면에서 업종코드로 다시 판정합니다. 분류 표를 고쳐도 지난달 스냅샷은 옛 판정을 담고 있기 때문입니다.

## 국민연금 API 호출 규격

`api/nps.js`는 다음 규격에 맞춰 요청합니다. 어긋나면 게이트웨이가 `국민연금 API 오류 97: CLIENT_ERROR`로 응답합니다.

- 목록 조회 `numOfRows`는 한 페이지 **최대 100건**입니다. 전량 수집은 100건씩 여러 장을 이어 받습니다.
- 상세조회 `getDetailInfoSearchV2`는 `seq`만 받습니다. 기준월(`dataCrtYm`)은 넘기지 않습니다.
- 조회 조건 파라미터 표기(카멜 `wkplNm` / 스네이크 `wkpl_nm`)와 법정동코드 형식(하위 코드만 `110` / 상위 코드 포함 `29110`)은 문서마다 설명이 엇갈립니다. 프록시는 네 조합을 순서대로 시도해 결과가 나오는 조합을 골라 기억하고, 첫 페이지가 0건이거나 파라미터 오류가 나면 다음 조합으로 넘어갑니다.
- 결과가 0건이면 응답의 `meta`에 시도한 조합과 요청 URL(서비스키는 가림)이 담깁니다. 브라우저 콘솔의 `[nps] 조회 결과 없음` 로그에서 확인할 수 있습니다.

### 오퍼레이션별로 주는 항목이 다릅니다

- 목록 `getBassInfoSearchV2`: 사업장명, 사업자등록번호 앞 6자리, 도로명주소, 가입상태, 사업장형태, 법정동코드, 자료생성년월. **업종코드가 없습니다.**
- 상세 `getDetailInfoSearchV2`: 위 항목에 더해 업종코드·업종명, 사업장 등록일·탈퇴일, 가입자 수, 당월 고지금액.
- 기간별 현황 `getPdAcctoSttusInfoSearchV2`: 월별 취득자 수, 상실자 수.

목록만으로는 업종·등록일·가입자 수를 알 수 없습니다. 그래서 조회 화면은 표를 먼저 그린 뒤 **미리 받아둔 동구 스냅샷에서 찾아 채우고, 스냅샷에 없는 사업장만 상세조회를 불러 채웁니다**(조회한 사업장 전부, 동시 4건, 한 조회당 900건까지). 스냅샷을 만들 때도 사업장마다 상세조회를 한 번 더 불러 업종을 채웁니다.
- `NPS_SERVICE_KEY`에는 **디코딩 키**를 넣습니다. 인코딩 키를 넣으면 키가 이중 인코딩되는데, 서버가 퍼센트 표기를 감지해 한 번 풀어 보정합니다.

## 환경변수

`.env.example`을 참고해 다음 키를 설정합니다.

```text
NTS_API_KEY=국세청_사업자상태조회_서비스키
SDSC_SERVICE_KEY=소상공인시장진흥공단_상가정보_서비스키
NPS_SERVICE_KEY=국민연금공단_가입사업장내역_서비스키
VWORLD_KEY=VWorld_2D데이터_API키
VWORLD_DOMAIN=https://biz-lookup.vercel.app
```

API 키는 브라우저 코드나 정적 JSON에 포함하지 않습니다.

## 데이터 갱신

```bash
npm install
npm run update-stores
npm run update-zones
npm run update-nps
```

국민연금 사업장 스냅샷은 `data/nps_donggu.json`에 저장되며 조회 화면의 업종·등록일·가입자 수를 채우는 데 쓰입니다. GitHub Actions `Update Dong-gu NPS snapshot` 워크플로가 매월 6일 04시(KST)에 돌리고, 저장소 Actions 탭에서 손으로도 실행할 수 있습니다. 목록 전량을 받은 뒤 사업장마다 상세조회를 한 번 더 부르므로 사업장 1만 개면 약 1만 1천 회를 호출합니다. `NPS_SERVICE_KEY` 저장소 Secret(**디코딩 키**)이 필요하며 없으면 워크플로가 첫 단계에서 멈춥니다. data.go.kr 트래픽 한도(개발계정 기본 1일 1만 회)를 넘기면 운영계정 전환이나 한도 상향을 신청해야 합니다.

스냅샷은 브라우저가 조회할 때 통째로 내려받으므로 화면이 실제로 읽는 값만 담습니다 — 같은 사업장인지 가리는 이름·사업자등록번호 앞 6자리·주소와, 목록 조회에 없어 채워야 하는 업종코드·업종명·등록일·탈퇴일·가입자 수입니다. 월별 이력의 `seq` 목록은 화면이 그때그때 받은 조회 결과에서 다시 만들므로 담지 않습니다.

상가 데이터는 `data/stores_donggu.json`, VWorld 주요상권 경계는 `data/mainbiz_zones_donggu.geojson`, 수동 등록·보정 경계는 `data/manual_mainbiz_zones_donggu.geojson`에 저장됩니다. GitHub Actions는 매월 5일 API 기반 데이터를 다시 수집하며 수동 경계는 별도 파일에 보존됩니다. `SDSC_SERVICE_KEY`와 `VWORLD_KEY` 저장소 Secret이 필요합니다.

현재 수동 등록 경계는 산수시장, 예술의 거리, 전자의 거리, 인쇄의 거리와 무등산 보리밥거리이며, 대인시장과 남광주시장은 VWorld 원본을 수동 보정 경계로 대체합니다.

VWorld 주요상권 중 금남로4가역 1~4와 문화전당역 경계는 수집 결과와 화면에서 제외합니다.
